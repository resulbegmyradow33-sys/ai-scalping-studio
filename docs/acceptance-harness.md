# Acceptance harness: real chain on synthetic data

`scalping.acceptance` is a single, deterministic end-to-end run. It does not
teach the system a strategy and it does not produce market evidence. It proves
that the real modules still connect, in order, and that each one leaves an
auditable artifact behind.

## What it runs

The stages are fixed and executed in this order:

| Stage | Real module exercised | Artifact |
|---|---|---|
| `import_validate` | `data.synthetic`, `data.store`, `data.validate` | temporary Parquet store, `validation.json` |
| `dataset` | `datasets.builder` | `dataset.json` |
| `discovery` | `discovery.run` with a small trial budget | `discovery.json`, `discovery.sqlite` |
| `evidence` | `discovery.evidence.build_evidence` | `evidence.json` |
| `promotion` | `discovery.promotion.evaluate_promotion` with an explicit acceptance test policy | `promotion.json` |
| `holdout` | `discovery.holdout`, only when that module is importable | `holdout.json`, `holdout.sqlite` |
| `paper_advance` | `paper.autonomous.AutonomousPaperRunner` and `paper.ledger` | `paper.json`, `paper.sqlite` |
| `matured_outcomes` | `paper.continuous.matured_outcomes` | `outcomes.json` |

The synthetic store is a one-day (configurable) XAUUSD M1 tape generated by
`SyntheticProvider`. Weekends produce no bars, so a weekend-only range fails at
the first stage with a typed result. The store lives under the system temporary
directory and is removed after the run unless `--keep` is passed.

The discovery search is intentionally tiny (`--max-trials`, default 6). It is
enough to exercise the archive, evaluator, gate and decision writer; it is not a
search for an edge. `NO TRADE` is a valid discovery outcome. If the discovery
winner cannot produce per-fold evidence on such a small sample, the evidence
stage records why and builds evidence for a deterministic long/holding-limit
fixture instead. That fallback is labelled in the report
(`candidate_source=acceptance_fixture`); it is not presented as a discovered
strategy.

## What the report says

Each run writes `runs/acceptance/<acceptance-id>/report.json`. The id is derived
from the execution inputs (symbol, dates, seed, window, trial budget, folds,
cost stress), not from the output directory, so the same experiment has a stable
identity.

Every stage records `status`, `detail`, artifact paths, checksums and counts. A
stage that raises stops the run, writes the report with that stage marked
`failed`, appends no later stages and raises `AcceptanceError`. The CLI prints
the typed result and exits non-zero. A failed run never invents a metric to keep
going.

The `claims` block is deliberately conservative:

```json
{
  "implemented": true,
  "tested": true,
  "validated": false,
  "paper_traded": false,
  "profitable": false
}
```

`implemented` and `tested` describe the code path and its tests. `validated`,
`paper_traded` and `profitable` are **false** because this run cannot prove any
of them. The `scope` block repeats the same distinction: synthetic data, no
out-of-sample result, no market evidence and no real money.

## What it does not prove

- **No out-of-sample validation.** Evidence is built from chronological
  train/validation folds. The dataset's test split is not read. Without a locked
  holdout, the promotion decision is rejected by design; a synthetic holdout
  attachment is still not market OOS evidence.
- **No profitability.** A small synthetic sample cannot establish an edge. A
  passing harness says the plumbing works, not that a strategy makes money.
- **No forward paper-trading evidence.** The paper runner writes a real local
  ledger, but the bars are synthetic and the session is a few dozen bars. That
  is an engine check, not a paper-trading trial with immutable forward
  attribution.
- **No target-hardware acceptance.** Runtime is measured by the test suite, not
  by a Mac mini M2 8 GB acceptance protocol.
- **No research-document ingestion.** Knowledge extraction, hypothesis routing
  and the locked-holdout protocol are separate slices; the harness only imports
  the holdout module when it exists.

## Exact command

From the repository root:

```bash
cd backend
uv run python -m scalping.cli acceptance run --out runs/acceptance
```

Use `--keep` to retain the temporary synthetic bar store (its path is printed
and stored in the report):

```bash
uv run python -m scalping.cli acceptance run --out runs/acceptance --keep
```

Useful knobs for a faster or slightly larger run:

```bash
uv run python -m scalping.cli acceptance run \
  --start 2026-01-05 --days 1 --seed 7 \
  --window 20 --max-trials 6 --paper-bars 120 \
  --out runs/acceptance
```

The command prints exactly one JSON line to stdout. On success it exits `0`; a
stage failure prints the typed failed report on stdout and exits `1`.

## Library use and tests

```python
from pathlib import Path

from scalping.acceptance import AcceptanceConfig, AcceptanceError, run_acceptance

config = AcceptanceConfig(out=Path("runs/acceptance"), keep=False)
try:
    result = run_acceptance(config)
except AcceptanceError as error:
    print(error.stage, error.code, error.result.report_path)
else:
    print(result.status, result.report_path, result.claims)
```

`backend/tests/test_acceptance.py` covers the passing run, determinism, the
typed failure path, the one-line CLI contract and the absence of network,
real-store and real-money access. It runs in seconds and is suitable for CI.
